Document control, what changed

The rest of the Hub is exactly as it was. Three things are new, and all three exist to show the back-end team what the document control layer has to do. Every link below opens the live prototype.

TQ-QHSE-S001 · ISO 9001:2015 7.5 · API Spec Q2 3rd Ed. 4.4, 4.5
Prototype. Document titles are real. The revision, approval, review and status values are generated to make the controls work end to end. The schema is the deliverable, it is the contract the back end must satisfy.

4Who can see and control the register

Four roles, switchable in the Master List nav. The split is deliberate: role decides which functions you get, classification decides which documents. The register itself stays readable by every employee, restricting it to QMS would breach 5.5, which requires Policies and Guidelines to be accessible to all, and a supervisor needs to confirm the current revision before starting a job.

Important

This is not security

Role switching runs in the browser and proves nothing, anyone can open a page directly or read the data file. It is a specification, so IT can implement the same matrix server-side: Entra ID group → SSO claim → per-record authorization, with the API returning only what the caller may see.

5What QHSE has to decide

Applying the standard in code is what exposed these. None of them can be fixed in the Hub.

Blocked

Four short forms are missing

Cybersecurity and the Learning Center have no short form in 5.3, the Learning Center owns this platform and cannot legally number its own documents. Technical Alert and Lesson Learned are not document types in 4.

Non-compliance

Retention says five years

TQ-QHSE-S001 7.5 sets five years, with ten as an API Q1 and medical exception. API Q2 3rd Edition 4.5 requires ten years for all records. The register already shows ten.
